Technical Documentation & API Specs

OmniLang SME Commerce Agent is a multimodal, multilingual conversational commerce platform built on Google Cloud (Gemini 2.5 Flash/Pro, Vertex AI Translation API, Dialogflow CX, Cloud Firestore, and Cloud Run). It enables micro-SMEs across JAPAC (Indonesian warungs, Philippine sari-sari stores & weavers, Indian karigars) and globally (LATAM, Africa) to generate SEO-optimized global listings from raw smartphone photos and negotiate with international buyers in real time over WhatsApp and LINE.

1. Detailed System Architecture & Clean Dependency Rule

OmniLang enforces a strict 4-layer Clean Architecture. The inner domain and application layers have zero framework or Google Cloud SDK dependencies. Every external concern (Gemini 2.5 Flash, Vertex AI Translation, Cloud Storage, Firestore, WhatsApp Cloud API, LINE Messaging API, and cross-border payment gateways) implements a typed port in the infrastructure layer and is injected at the composition root (src/interface/container.ts).

End-to-End Conversational State Machine & Dataflow

Every buyer-merchant conversation is modeled by the Negotiation aggregate, mirroring the Dialogflow CX state machine lifecycle with strict transition guards and immutable turn transcripts:

┌───────────┐ Merchant Counter-Offer ┌───────────┐ Buyer Accepts Terms ┌───────────┐ │ INQUIRY ├───────────────────────────────►│ OFFER ├───────────────────────────►│ SHIPPING │ └───────────┘ (RelayChatMessageUseCase) └─────┬─────┘ (RelayChatMessageUseCase) └─────┬─────┘ │ ▲ │ └─┘ Counter-Offer Loop │ CloseDealUseCase ("bisa nego tipis") ▼ ┌───────────┐ Escrow Webhook Settled ┌───────────┐ │ PAID │◄───────────────────────────┤ INVOICED │ └───────────┘ └───────────┘

Cloud Firestore Data Model & Composite Indexes

In production mode (OMNILANG_PERSISTENCE=firestore), entities round-trip through deterministic JSON snapshots across three root collections (listings, negotiations, orders). Deploy the following composite indexes via firestore.indexes.json:

Collection Composite Index Fields Query Purpose
negotiations channel ASC, buyerAddress ASC, stage ASC, updatedAt DESC Resolve active negotiation (INQUIRY | OFFER | SHIPPING) for inbound buyer webhook in O(1) index scan.
negotiations channel ASC, merchantAddress ASC, stage ASC, updatedAt DESC Route merchant WhatsApp/LINE reply back to the most recent active international buyer session.
listings / negotiations merchantId ASC, updatedAt DESC Aggregator dashboard & merchant catalog lookup ordered by recency.

2. API Request / Response Contracts

All endpoints accept and return UTF-8 JSON. Below are the production request/response schemas and status codes (machine-readable OpenAPI 3.1 specification available at /openapi.json).

POST /api/merchants/:merchantId/listings
Use Case: CatalogProductPhotoUseCase

Uploads a raw product photo + colloquial merchant note in Bahasa Indonesia (id), Tagalog (tl), Hindi (hi), or Vietnamese (vi). POST /webhooks/whatsapp
Use Case: RelayChatMessageUseCase & CatalogProductPhotoUseCase

Receives inbound Meta WhatsApp Business Cloud API webhook payloads. Automatically classifies sender against the Merchant Directory: buyer messages open or continue a Negotiation and translate into the merchant's dialect; merchant replies translate into the buyer's language and advance the Dialogflow CX stage.

POST /webhooks/line
Header: x-line-signature (HMAC-SHA256)

Validates the raw request buffer against LINE_CHANNEL_SECRET using timing-safe HMAC-SHA256 verification before routing text and image events to the application use cases.

Deterministic Error Handling Contract

Domain / Application Error HTTP Status Response Shape Trigger Condition
ZodError / ValidationError / InvalidTransitionError 400 Bad Request { "error": "...", "issues": [...] } Negative money/quantity, invalid currency code, or illegal state machine transition.
MerchantNotFoundError / ListingNotFoundError / NegotiationNotFoundError 404 Not Found { "error": "Entity '...' not found" } Unknown identifier requested via REST API.
MissingPriceInNote 422 Unprocessable Entity { "error": "No price found in the note..." } Merchant photo caption contains no parseable price (quantity chatter like "5 pcs" is rejected safely).
UpstreamServiceError 502 Bad Gateway { "error": "Upstream service failure" } External WhatsApp/LINE/Payment gateway timeout or non-2xx response.

Unit Economics & Tiered Monthly Cost Analysis (TCO)

OmniLang is engineered for micro-commerce unit economics where average order values (AOV) range from $25 to $75 USD. By combining deterministic domain parsing (parsePriceHint) with single-pass structured JSON output on gemini-2.5-flash, total AI + infrastructure cost per closed cross-border order is ~$0.015 USD (1.5 cents, or ~0.03% of GMV).

4. Comprehensive Setup Guide for Enterprise Merchant Aggregators

Enterprise merchant aggregators—such as craft cooperatives, national MSME ministries, cross-border logistics providers, and regional super-apps—can deploy and onboard thousands of merchants onto OmniLang in four steps:

Step 1: Bulk Merchant Directory Onboarding (MERCHANTS_JSON or Custom Directory Port)

Each micro-SME requires only five fields: id, displayName, language (id | tl | hi | vi | ja | en), currency (IDR | PHP | INR | VND | JPY | SGD | USD), channel (whatsapp | line), and address (E.164 phone number or LINE userId). 

export MERCHANTS_JSON='[
  {"id":"m-001","displayName":"Warung Sari Batik","language":"id","currency":"IDR","channel":"whatsapp","address":"6281234567890"},
  {"id":"m-002","displayName":"Tindahan ni Aling Rosa","language":"tl","currency":"PHP","channel":"whatsapp","address":"639171234567"},
  {"id":"m-003","displayName":"Jaipur Kala Studio","language":"hi","currency":"INR","channel":"whatsapp","address":"919876543210"}
]'

Enterprise CRM Integration: For dynamic 100k+ merchant directories, implement the 2-method MerchantDirectory port (findById, findByChannelAddress) in src/application/ports/merchant-directory.ts against your existing PostgreSQL/BigQuery/Firestore merchant table without modifying any use case.

Step 2: Provision Google Cloud IAM & Deploy to Cloud Run

Grant least-privilege IAM roles to the Cloud Run service account and deploy directly from source:

# 1. Enable required Google Cloud APIs
gcloud services enable run.googleapis.com aiplatform.googleapis.com translate.googleapis.com firestore.googleapis.com storage.googleapis.com

# 2. Deploy stateless container to Cloud Run (asia-southeast1)
gcloud run deploy omnilang \
  --source . \
  --region asia-southeast1 \
  --allow-unauthenticated \
  --set-env-vars "OMNILANG_PERSISTENCE=firestore,GCP_PROJECT=your-gcp-project,GCP_LOCATION=asia-southeast1,GEMINI_MODEL=gemini-2.5-flash,GOOGLE_CLOUD_STORAGE_BUCKET=omnilang-media,CATALOG_BASE_URL=https://omnilang.dev"

Step 3: Connect WhatsApp Business BSP & LINE Official Account Webhooks

Configure your Meta WhatsApp Business Solution Provider (360dialog, Twilio, or Meta Cloud API direct) and LINE Developers Console to forward events to your Cloud Run URL:

WhatsApp Webhook Callback URL : https://<your-cloud-run-url>/webhooks/whatsapp
WhatsApp Verify Token         : <WHATSAPP_VERIFY_TOKEN>
LINE Messaging Webhook URL    : https://<your-cloud-run-url>/webhooks/line

Step 4: Connect Cross-Border Escrow & Payment Rails (PAYMENTS_API_URL)

Set PAYMENTS_API_URL to your payment aggregator endpoint (e.g., Xendit, Stripe Connect, PayMongo, Razorpay). HttpPaymentProvider sends a POST request with { orderId, description, amount, currency } and attaches the returned { invoiceId, paymentUrl } to the bilingual buyer/merchant receipts.
